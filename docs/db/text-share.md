# DB — Text Share (Self-Destructing Text)

Manual queries for the **Text Share** tool. Run these in the Neon SQL console (or any PostgreSQL client). All statements are idempotent — safe to re-run.

## Tables

```sql
CREATE TABLE IF NOT EXISTS shared_texts (
  id TEXT PRIMARY KEY,
  code TEXT UNIQUE NOT NULL,
  content TEXT NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  expires_at TIMESTAMPTZ NOT NULL
);

CREATE INDEX IF NOT EXISTS idx_shared_texts_expires_at ON shared_texts(expires_at);
```

`id` and `code` are the same 10-char random base62 value generated by the API. `content` holds the raw shared text (max 10,000 chars, stored as plain data — never rendered as HTML).

## Rate-limit table (1 share / minute / IP)

```sql
CREATE TABLE IF NOT EXISTS shared_text_limits (
  ip TEXT PRIMARY KEY,
  last_share_at TIMESTAMPTZ NOT NULL
);
```

Used by `lib/textShare.ts` (`checkTextShareLimit` / `recordTextShare`). Same DB-backed pattern as the file transfer tool so the limit holds across serverless instances.

## How the API uses them

- `POST /api/tools/share-text` — `SELECT last_share_at FROM shared_text_limits WHERE ip = $1` → allow/429; on success `INSERT ... ON CONFLICT (ip) DO UPDATE SET last_share_at = NOW()` and `INSERT INTO shared_texts (id, code, content, expires_at) VALUES (..., $expiresAt)` where `$expiresAt` = now + chosen TTL (5 min / 1 hour / 24 hours).
- `GET /t/[code]` (server page) — `SELECT content, expires_at FROM shared_texts WHERE code = $1 LIMIT 1`; expired or missing → `DELETE FROM shared_texts WHERE code = $1` then 404.
- `GET /api/cron/cleanup-shared-texts` — `DELETE FROM shared_texts WHERE expires_at <= NOW() RETURNING id`. Protected by `x-cron-secret` (see `CRON_SECRET` env).
